# Промт для Флаба — экосистема seoshkin.tools

Скопировать целиком в новую сессию с Флабом.

---

## Задача

Навести порядок в экосистеме `seoshkin.tools` на сервере `gcloud-seosite`. Проект
`translate` (приложение для изучения языков) — один из арендаторов этого сервера, он
сейчас в активной разработке и на нём живые ученики. Ниже — что о нём нужно знать,
чтобы ничего не сломать, и что от тебя требуется.

## Что за проект translate

- Каталог на сервере: `/home/seosite/translate`, репозиторий отдельный.
- Стек: Fastify + React + PostgreSQL 16 в Docker Compose (`docker-compose.prod.yml`).
- Домены: **deutschlernen.ai** (основной) и **translate.seoshkin.tools** (редирект на первый).
- Приложение мультиязычное: немецкий, испанский, английский — одна база, один код.
- Данные: ~3000 слов, ~18000 упражнений, 7 активных учеников. **Прод рабочий.**

## ⛔ Границы: что трогать нельзя

**1. Конфиги nginx этого проекта — только через git репозитория translate.**

```
/home/seosite/translate/nginx/
  deutschlernen.ai.conf
  translate.seoshkin.tools.conf
```

Они монтируются в общий шлюз `seoshkin_nginx` как `conf.d/*.conf`. Источник истины —
git репозитория translate, не сервер. Правка на сервере руками будет затёрта при
следующем `git pull`. Если нужно изменить — скажи, я поменяю в репозитории.

Два правила оттуда же, чтобы не уронить ВСЕ сайты шлюза:
- `proxy_pass` только на имя контейнера `http://translate-frontend-1:80`. Внутри шлюза
  `127.0.0.1` — это сам шлюз, а не приложение. Частая причина «сайт лёг».
- Блок `443` нового домена включать **только после** выпуска сертификата. Иначе nginx
  не стартует (нет файла серта), и при пересоздании контейнера падают все сайты.

**2. Базу и тома данных проекта translate не трогать.** Тома `postgres_data` и
`uploads_data` (600 МБ картинок и сканов уроков). Бэкап перед любыми операциями с
диском — обязательно.

**3. Контейнеры проекта не пересоздавать без предупреждения.** Я деплою этот проект сам,
несколько раз в день. Если тебе нужен рестарт — скажи, согласуем.

## 🔥 Две проблемы, найденные 28.07.2026 — начни с них

**1. Сертификат seoshkin.com просрочен.** Сайт сейчас недоступен, браузер показывает
предупреждение безопасности:
```
SSL certificate problem: certificate has expired
```
Проверить остальные домены шлюза заодно и настроить автопродление так, чтобы это
не повторилось. Конфиг: `/var/www/seoshkin.com/nginx.conf`.

**2. Конфиги nginx монтируются НЕ оттуда, где их правят.** В шлюз смонтирован
`/var/www/translate.seoshkin.tools/nginx.conf`, а разработка ведётся в
`/home/seosite/translate/nginx/*.conf` (git). То есть правки в репозитории до сервера
не доезжали вообще — их приходилось дублировать руками, и файлы успели разойтись.

Это уже привело к аварии: старый домен стоял в режиме 301-редиректа, из-за чего в
Android-приложении не работал вход (POST на /api/auth/login получал редирект и терял
тело запроса) и не обновлялся интерфейс. 28.07 я привёл серверный файл в соответствие
с git вручную (бэкап рядом: `nginx.conf.bak-20260728`), но правильного решения нет.

Нужно сделать так, чтобы источник истины был один. Как — на твоё усмотрение: монтировать
каталог из репозитория, собирать конфиг при деплое, симлинк. Главное, чтобы правка в git
доезжала до шлюза без ручного копирования.

## Что нужно от тебя

1. **Порядок в экосистеме** — как ты считаешь правильным: структура каталогов, единый
   подход к compose-файлам, бэкапы, мониторинг, сертификаты.
2. **Подготовить схему для новых доменов.** Павел покупает узкопрофильные домены под
   каждый язык (изучение испанского, английского и т.д.). Все они должны вести на **то же
   самое приложение** translate — это не новые проекты. Нужна понятная, повторяемая
   процедура: добавить домен → выпустить серт → подключить к шлюзу.
3. **Ревью инфраструктуры на предмет рисков**: что упадёт при перезагрузке сервера, где
   нет бэкапов, где однажды кончится диск.

## Чего делать НЕ надо

- Не переносить translate на другую схему деплоя без обсуждения — он деплоится
  автоматически много раз в день, любая смена процесса ломает мой цикл.
- Не «оптимизировать» docker-compose проекта translate.
- Не менять порты и имена контейнеров: `translate-frontend-1`, `translate-backend-1`,
  `translate-db-1` прописаны в конфигах шлюза.
