> **Павел, 28.07.2026:** «Когда я скажу, что мы будем выкладываться на Google Play —
> обязательно вспомни про это и перепроверь».
> Ассистент: при первом же упоминании Google Play открыть этот файл и пройти по пунктам.

---

## ⚠️ Главный риск: ключ подписи

Google Play привязывает приложение к ключу **навсегда**. Если собрать AAB другим ключом:

- Play **откажется принимать обновление** для уже опубликованного приложения;
- откатить это нельзя — только публиковать заново под новым `packageId`,
  то есть потерять всех установивших, отзывы и статистику.

**Ключ лежит вне репозитория (и правильно):**

```
../translate.seoshkin.tools-android-keys/
  android.keystore          alias: android, RSA 2048, срок 30 лет
  keystore-password.txt     storepass и keypass одинаковые
```

**Отпечаток на 28.07.2026** (зафиксирован здесь, чтобы было с чем сверять):

```
SHA-256: 46:00:A3:6D:C2:A6:B2:90:D3:6B:6C:BF:C6:4D:25:7E:4E:DE:D7:C5:B8:8A:69:13:5D:9C:8A:BA:B1:F1:5E:61
```

Он же прописан в `frontend/public/.well-known/assetlinks.json` — именно этот файл убирает
адресную строку браузера внутри приложения. Проверено: отдаётся с `deutschlernen.ai`.

## Порядок действий

### 1. Сверить ключ — ДО сборки

```bash
keytool -list -v \
  -keystore ../translate.seoshkin.tools-android-keys/android.keystore \
  -alias android | grep SHA256
```

Отпечаток обязан совпасть со строкой выше **и** со значением в `assetlinks.json`.
**Не совпал — остановиться и разобраться, не собирать.**

⚠️ На машине Павла (28.07.2026) `keytool` есть, но **Java не установлена** —
команда падает с «Unable to locate a Java Runtime». Для сборки понадобится JDK.

### 1b. Вживить виджет — между `update` и `build`

```bash
./apply-widget.sh
```

`bubblewrap update` создаёт проект заново, и виджет домашнего экрана из него пропадает.
Сборка без этого шага пройдёт успешно и выпустит APK **без виджета** — молча. Проверить,
что виджет на месте, можно по собранному файлу:

```bash
aapt2 dump xmltree app-release-signed.apk --file AndroidManifest.xml | grep DailyGoalWidget
```

Пусто — не выкладывать, вернуться к скрипту.

### 2. Сделать резервную копию ключа

Потеря keystore = потеря приложения в Play. Копия должна лежать вне ноутбука
(парольный менеджер или зашифрованный бэкап), а не только в соседней папке.

### 3. Домен в манифесте — ✅ сделано 23.08.2026

`android-twa/twa-manifest.json` переведён на `deutschlernen.ai`: `host`, `webManifestUrl`,
`fullScopeUrl`, обе иконки. Проверено, что новый домен отдаёт всё, на что ссылается
манифест (`manifest.webmanifest`, `icons/icon-512.png`, `icons/icon-512-maskable.png`,
`.well-known/assetlinks.json` — все 200).

Старый домен `translate.seoshkin.tools` остался в `additionalTrustedOrigins`. Он не
редиректит, а работает сам по себе (проверено: отдаёт 200 и тот же `assetlinks.json`
с тем же отпечатком), поэтому ссылка на него изнутри приложения без этой записи
открывалась бы в браузере с адресной строкой.

`packageId` (`tools.seoshkin.translate`) не трогаем никогда: он связан с ключом подписи,
и его смена означает новое приложение в Play, а не обновление.

### 4. Поднять версию

`appVersionCode` — целое число, **строго больше** предыдущего, иначе Play отклонит,
а APK с сайта не встанет обновлением поверх установленного.
На 23.08.2026 в манифесте: `appVersionCode: 2`, `appVersionName: "1.0.1"` — подняты
вместе со сменой домена, но **сборки с ними ещё не было**. Если следующая сборка
случится после других правок, версию поднять снова.

### 5. Собрать

```bash
cd android-twa
BUBBLEWRAP_KEYSTORE_PASSWORD="$(cat ../../translate.seoshkin.tools-android-keys/keystore-password.txt)" \
BUBBLEWRAP_KEY_PASSWORD="$(cat ../../translate.seoshkin.tools-android-keys/keystore-password.txt)" \
npx @bubblewrap/cli build
```

Для Play нужен `app-release-bundle.aab`, для сайта — `app-release-signed.apk`.

### 6. Проверить подпись собранного файла

```bash
keytool -printcert -jarfile app-release-bundle.aab | grep SHA256
```

Снова сверить с отпечатком выше. Это последняя точка, где ошибку ещё можно поймать.

### 7. Проверить на устройстве

Установить APK и убедиться, что **адресной строки браузера нет**. Если она появилась —
`assetlinks.json` не сошёлся с ключом или не отдаётся с домена; в Play в таком виде идти нельзя.
