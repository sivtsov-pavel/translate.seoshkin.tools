# HANDOFF: локальные модели + правки deutschlernen.ai (27.07.2026)

Документ-передача из сессии по экосистеме (seoshkin.tools). Всё, что ниже, — факты,
проверенные вживую. Новая сессия работает в этой папке (`translate.seoshkin.tools`).

## Главное правило (не нарушать)
**Платные API = реальные деньги Павла.** Любая операция, тратящая баланс OpenAI, —
только после явного согласия. Локальные модели (Ollama, Draw Things) бесплатны и
предпочтительны. Найденная утечка денег: перерисовка картинок через `gpt-image-1`
стоила ~3–4 цента за штуку; в базе 2737 слов → так ушли десятки-сотни долларов.

## Что уже сделано и закоммичено (не переделывать)
1. **`backend/src/services/localAi.js`** — новый сервис:
   - `makeOllamaClient()` — OpenAI-совместимый клиент Ollama (подменяет модель,
     vision-запросы уводит на мультимодальную `gemma3:4b`, `json_schema` → `json_object`);
   - `generateImageLocally(prompt)` — картинки через Draw Things (A1111 API, порт 7860);
   - `localAiHealth()` — доступность локальных сервисов.
2. **`openaiClient.js`** — при `AI_TEXT_PROVIDER=local` платформенный клиент = Ollama;
   `getOwnerClient()` в локальном режиме не лезет за ключами владельцев.
3. **`imageGen.js`** — при `AI_IMAGE_PROVIDER=local` рисует Draw Things; при сбое
   НЕ уходит молча в платный OpenAI (возвращает null).
4. **`config.js`** — новые переменные: `aiTextProvider`, `aiImageProvider`,
   `ollamaBaseUrl`, `ollamaModel`, `ollamaVisionModel`, `drawThingsUrl`.
5. **`docker-compose.yml`** — те же переменные проброшены в backend (по умолчанию
   `openai`, локальный режим включается только через `.env` — на прод не уедет).
6. **`GET /api/settings/ai-providers`** — статус провайдеров для переключателя в UI.
7. **`PATCH /api/admin/users/:userId/role`** (admin.js) — супер-админ назначает роль
   owner/student. Раньше учителем можно было стать ТОЛЬКО при регистрации с почтой из
   жёсткого списка `OWNER_EMAILS`. **Задеплоено на прод.**
8. **Фикс видимости для учителя** (`routes/lessons.js`): было `owner_id = сам` — второй
   учитель школы не видел ничего и знал меньше своих учеников. Стало: уроки своей школы
   + свои личные. **Задеплоено на прод, проверено Павлом (у Serkopa появился словарь).**
9. **nginx**: `translate.seoshkin.tools` → 301 на `deutschlernen.ai` (чинит старые
   ссылки-приглашения и конфликт прав из-за разных origin). Эталон конфига в git.

## 🐛 БАГ, КОТОРЫЙ НУЖНО ПОЧИНИТЬ В КОДЕ (главная задача)
`imageGen.js` передаёт в модель **русский** концепт (`translationRu`). OpenAI русский
понимал, локальная модель — НЕТ: она рисует НАДПИСЬ. Реальный случай: «стол» → картинка
с буквами «СТОЛ» вместо стола.

**Решение (проверено в скрипте):** перед генерацией переводить понятие на английский
локальной моделью (бесплатно, ~1–2 с):
```
Translate this word to English. Answer with ONE English word only, nothing else.
Russian: "<translationRu>" (target: "<wordDe>")
```
Результат («стол» → «Table») подставлять в промпт картинки. После фикса: стол, чемодан,
рука нарисованы правильно. Делать это только в локальном режиме (для OpenAI не нужно).

## 📋 Задача: перерисовать фото Unsplash в рисовашки
- В испанском словаре (курс «Español — Alfabetización») **125 слов**: **36 с фото
  Unsplash** (расширение **`.jpg`**) и **89 рисовашек** (`.webp`, генерились ИИ).
- **Маркер простой и точный: `.jpg` = фото Unsplash, `.webp` = рисунок ИИ.**
  Независимо подтверждено локальной vision-моделью (36 «фото» = ровно все .jpg).
- Перерисовать нужно **только 36 .jpg**; рисовашки не трогать — они общие для всех
  языков в банке слов.
- Готовый скрипт-прототип (генерация + перевод концепта + сжатие в webp) лежит в
  песочнице прошлой сессии; логику проще перенести в код приложения.
- Картинки лежат на ПРОДЕ, а рисуются на ноуте → цепочка: генерация локально → заливка
  файлов на сервер → обновление `words.image_url` (старые .jpg не удалять, откат простой).
- ⚠️ Перед массовым обновлением прод-базы — бэкап (последний: `/home/seosite/backup-before-school-fix-20260727.sql.gz`).
